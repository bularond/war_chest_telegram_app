# Сундук войны — Telegram Mini App

Дуэль по правилам настольной War Chest (Trevor Benjamin, David Thompson, AEG):
драфт отрядов, мешок монет, гекс-поле, победа по контрольным маркерам.
Сервер авторитетный, правила живут в общем пакете и гоняются и на клиенте, и на
сервере.

## Что внутри

| Пакет | Что делает |
| --- | --- |
| `packages/shared` | Гексы, доска, каталог отрядов, движок правил, протокол. Ноль зависимостей. |
| `packages/server` | Fastify + WebSocket + SQLite. Проверка подписи Telegram, лобби, партии, история. |
| `packages/client` | Vite + React. Экраны меню, лобби, драфта и партии. |
| `design/` | Макет из Claude Design и официальный рулбук, из которого восстановлена доска. |
| `warchest.units.clean/`, `war_chest_pnp/` | Развёртка карт и print-and-play монеты — источник данных и графики. |
| `docs/RULES.md` | Откуда взяты правила и как решены спорные места. |
| `CLAUDE.md` | Карта кода и договорённости: с чего начинать правку. |

## Запуск

```bash
npm install
npm run build
npm test          # 256 тестов: правила, данные карт, геометрия доски, фаззинг партий, боты и арена, рендер UI
```

Разработка — два процесса:

```bash
npm run dev -w @wc/server     # :8787
npm run dev -w @wc/client     # :5173, проксирует /ws на сервер
```

Открыть `http://localhost:5173`. Без токена бота сервер работает в dev-режиме:
подпись Telegram не проверяется, личность берётся из `localStorage`. Чтобы
сыграть с собой — второе окно в приватной вкладке.

Прогнать полную партию через сервер по WebSocket:

```bash
npm run build && node packages/server/dist/index.js &
npm run smoke
```

## Боевой режим

В одну команду, через Docker:

```bash
npm run deploy        # docker compose up -d --build
```

Собирается всё внутри образа (`shared` → `bots` → `server` → `client`), наружу
торчит один контейнер: сервер сам отдаёт собранный клиент. База — профили и
история — лежит в томе `war-chest-data`, поэтому переживает пересборку; лобби и
партии живут в памяти и умирают вместе с контейнером.

Настройки берутся из окружения или из `.env`, если он есть. Для настоящего
развёртывания:

```bash
cp .env.example .env      # TELEGRAM_BOT_TOKEN=... и NODE_ENV=production
npm run deploy
```

Без токена сервер поднимется в dev-режиме — подпись Telegram не проверяется,
личность берётся из `localStorage`. Это удобно, чтобы посмотреть сборку
локально той же командой. Порт снаружи — `PORT` (по умолчанию 8787):
`PORT=8788 npm run deploy` поднимет рядом со всем, что уже занимает 8787.

Дальше: `docker compose logs -f`, `docker compose down`, а
`docker compose down -v` снесёт и базу.

### На VPS

Контейнер слушает только `127.0.0.1` — наружу смотрит nginx, он же держит TLS,
без которого Telegram Mini App не откроет. Готовый конфиг для
`warchestapp.bularond.ru` лежит в
[`deploy/nginx/`](deploy/nginx/warchestapp.bularond.ru.conf); в нём важны две
вещи, которые легко забыть: проброс заголовков `Upgrade` для `/ws` и
`proxy_read_timeout` — иначе игрока, задумавшегося над ходом дольше минуты,
выбрасывает со стола. И никаких `X-Frame-Options`: Telegram Desktop открывает
приложение в iframe.

```bash
# на сервере: код, ключи, запуск
git clone <репозиторий> war_chest && cd war_chest
cp .env.example .env && $EDITOR .env      # токен, NODE_ENV=production
docker compose up -d --build

# TLS и фронт
sudo certbot certonly --nginx -d warchestapp.bularond.ru
sudo cp deploy/nginx/warchestapp.bularond.ru.conf \
        /etc/nginx/sites-available/warchestapp.bularond.ru
sudo ln -s /etc/nginx/sites-available/warchestapp.bularond.ru /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

Если на VPS меньше двух гигабайт памяти, сборка образа на нём может не влезть.
Тогда собрать у себя и перевезти готовый образ:

```bash
docker build -t war-chest:latest . && docker save war-chest:latest | gzip \
  | ssh vps 'gunzip | docker load'
ssh vps 'cd war_chest && docker compose up -d'   # build: не нужен, образ уже есть
```

Последний шаг — BotFather: `/newapp`, Web App URL
`https://warchestapp.bularond.ru`.

Вручную, без Docker:

```bash
export TELEGRAM_BOT_TOKEN=123456:AA...    # обязателен при NODE_ENV=production
export NODE_ENV=production
export PORT=8787
npm run build
node packages/server/dist/index.js
```

Сервер отдаёт собранный клиент из `packages/client/dist`, так что снаружи нужен
один HTTPS-домен. Дальше в BotFather: `/newapp` → указать этот домен как Web App
URL. Telegram передаёт `initData`, сервер проверяет HMAC-подпись ботовым токеном
и отклоняет всё, что старше суток.

Переменные окружения: `PORT`, `HOST`, `DB_PATH`, `CLIENT_DIR`, `LOG_LEVEL`.

Бот: `BOT_WORKERS` — сколько ходов считается одновременно (по умолчанию 2;
поднимать только при запасе ядер), `BOT_THINK_MS` — минимальная пауза на ход
(600), `BOT_DEADLINE_MS` — после какого времени ход бросают и заменяют воркер
(5000). Уровни: простой считает эвристикой, средний и сложный — поиском с
бюджетом 250 и 1000 мс.

## Как устроена партия

1. **Раздача отрядов.** Хозяин выбирает при создании стола один из трёх
   способов:
   - *обычный драфт* — восемь карт из шестнадцати в ряд, разбор по очереди
     1–2–2–2–1; кто выбирал вторым, ходит первым;
   - *драфт с банами* — «elimination draft» из турнирного набора AEG: карт
     раздаётся на две больше, каждая сторона вычёркивает одну, дальше обычный
     драфт;
   - *случайно* — по четыре отряда каждому сразу, инициатива у первого места.
2. **Раунд.** Оба берут по 3 монеты из мешка (в мешке 9: по две каждого своего
   отряда плюс королевская). Ходы по очереди, по монете за ход, пока руки не
   опустеют. Мешок пуст — в него замешивается сброс.
3. **Действия.** Ровно одно на монету:
   - на поле: *развернуть*, *усилить*;
   - рубашкой вниз: *инициатива*, *наём*, *пас*;
   - лицом вверх (манёвр): *ход*, *атака*, *захват*, *тактика*.
4. **Победа.** Кто выставил все шесть контрольных маркеров. Два стоят на
   стартовых локациях, значит захватить надо ещё четыре.

Скрытая информация настоящая: рука соперника, содержимое мешков и монеты,
сброшенные рубашкой вниз, на клиент не уходят — сервер режет состояние в
`viewFor()`.

## Данные отрядов

Тексты карт, число монет и способности всех 16 базовых отрядов перенесены с
самих карт (`warchest.units.clean/`). Сумма монет даёт 74 — ровно столько в
списке компонентов рулбука, и это проверяется тестом.

Стартовые локации сверены с диаграммой сетапа на стр. 4 рулбука: стороны стоят
друг напротив друга по короткой оси поля, тёмная сверху (`4,0`, `7,0`), светлая
снизу (`3,4`, `6,5`). Поле показывается каждому так, чтобы его базы были снизу.

Подробности и решения по спорным местам — в [`docs/RULES.md`](docs/RULES.md).

## Графика

Монеты, королевские монеты и контрольные маркеры — print-and-play ассеты из
`war_chest_pnp/`, скопированные в `packages/client/public`. По одному PNG на тип
отряда; цвет диска и белый знак уже в картинке, приложение ничего не
подкрашивает. Королевская монета печатается для двух фракций, поэтому берётся по
месту за столом.

Клетки поля — четыре SVG-тайла (`public/board`): пустая, нейтральная локация с
кельтским узлом и по одной на каждую сторону с её контрольным маркером. Собирает
их `download_assets.py`; поверх каждого тайла лежит прозрачный шестиугольник —
он и ловит тап, и подсвечивает допустимые клетки.

Лицо игрока — фото из Telegram, а если его нет, королевская монета его стороны
(чёрный ворон или золотой лев), как в коробке. Фракций в наборе ассетов две, так
что места 3 и 4 их переиспользуют.

## Дополнения

Все три официальных дополнения реализованы и включаются тоглами при создании
стола: **Знать** (7 королевских указов, печати, действие «проклэйм»), **Осада**
(укрепления, десять раскладок, осадные тактики) и **Ночная вылазка** (яд и
обманные монеты). Каждое добавляет свои четыре отряда в драфт-пул.
