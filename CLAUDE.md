# CLAUDE.md

Telegram Mini App: дуэль по правилам настольной War Chest (Trevor Benjamin,
David Thompson, AEG). Монорепозиторий npm workspaces, TypeScript, ESM везде.

Подробности правил и источники — [`docs/RULES.md`](docs/RULES.md), запуск и
боевой режим — [`README.md`](README.md), план компьютерного соперника —
[`ROADMAP.md`](ROADMAP.md). Здесь — карта кода и договорённости.

## Команды

```bash
npm install
npm run typecheck                # tsc -b по всем пяти пакетам
npm test                         # 129 движок + 116 боты + 87 арена + 26 сервер + 27 клиент
npm run build                    # shared → bots → server → client
npm run deploy                   # docker compose up -d --build: один контейнер, том под базу
npm run dev -w @wc/server        # :8787, node --watch
npm run dev -w @wc/client        # :5173, проксирует /ws на сервер
npm run smoke                    # полная партия через WebSocket по-настоящему
npm run fuzz -- --games 20000    # тяжёлый фаззер: случайные партии до первой поломки
npm run arena -- --a heuristic --b greedy --games 200  # матч ботов с интервалом
npm run bench                    # стоимость операций движка, роллаутов и поиска
npm run sprt -- --a weights/base.json --b weights/новое.json   # принять или откатить правку весов
npm run spsa -- --from weights/base.json --out weights/spsa.json   # двигать все веса разом, потом подтвердить через sprt
npm run ladder -- --weights weights/lab.json    # насколько три уровня различаются на самом деле
npm run regress -- --games 5000 --out weights/fitted.json   # подогнать все веса по исходам самоигры
npm run regress -- --target value --weights weights/lab.json --games 250 --out weights/fitted-value.json   # мишень — оценка поиска, играющего этими весами
npm run lab -- --plan weights/night.plan.json --out weights/lab --resume --descent   # очередь экспериментов на ночь
node scripts/lab-watch.mjs        # одна строка о состоянии ночного прогона
node scripts/lab-report.mjs       # чем ночь кончилась: вердикты, принятые шаги, подтверждение
node scripts/lab-verdicts.mjs     # по строке на каждый решённый эксперимент, для монитора
node scripts/feature-drift.mjs    # читает ли фича позицию или форму поиска — до матча, а не после
node scripts/root-parallel.mjs    # во что превращается лишнее ядро: N деревьев стоят скольких итераций в одном
```

Ночной прогон запускается так — `caffeinate` обязателен, иначе ноутбук уснёт по
бездействию и всё встанет:

```bash
nohup node packages/tooling/dist/lab-cli.js --plan weights/night.plan.json \
  --out weights/lab --resume --budget-ms 250 --max-games 800 \
  --max-minutes 40 --max-plies 1200 --jobs 13 --descent >> weights/lab.log 2>&1 &
nohup caffeinate -i -w $(pgrep -f lab-cli.js | head -1) > /dev/null 2>&1 &
```

`-w <pid>` привязывает удержание ко времени жизни самой лаборатории: голый
`caffeinate -i` за ночь потерялся, и машину держали от сна чужие ассерции, на
которые рассчитывать нельзя. Проверять — `pmset -g | grep '^ sleep'`, там должно
быть «prevented by caffeinate».

Одиночный тест: `npx vitest run packages/shared/src/siege.test.ts`,
`npx vitest run -t "часть имени"`.

Вне Telegram сервер работает в dev-режиме: подпись не проверяется, личность
берётся из `localStorage`. Чтобы сыграть с собой — второе окно в приватной
вкладке, иначе оба таба сядут за стол одним игроком.

## Пакеты

| Пакет | Роль |
| --- | --- |
| `@wc/shared` | Правила игры. Ноль зависимостей, гоняется и на сервере, и в браузере. |
| `@wc/server` | Fastify + `@fastify/websocket` + `node:sqlite`. Авторитетный. |
| `@wc/client` | Vite + React 19. Только отрисовка и выбор действия. |
| `@wc/bots` | Компьютерные соперники. Видят `GameView`, не `GameState`. |
| `@wc/tooling` | Оффлайн-инструменты: арена, статистика. CLI, без сети и базы. |

Зависимость строго в одну сторону: все знают про `shared`, `shared` не знает ни
про кого. `tooling` знает про `bots`, обратной стрелки нет.

## Как это работает

**Сервер авторитетный.** `GameState` не покидает сервер; клиент получает
`GameView` от `viewFor()`, где вырезано скрытое: мешки, чужая рука, монеты,
сброшенные рубашкой вниз. Клиент никогда не считает правила сам — он только
сужает список `view.legal`, который прислал сервер.

**Шаги.** Всё, что игрок ещё должен решить, лежит в `state.pending` —
стек `PendingStep`, разбирается с конца. Шаг может нести поле `seat`: тогда
отвечает не тот, чей ход, а защищающийся (`actingSeat`). Так сделан выбор
«принять удар на себя».

**Выбор действия в клиенте.** Действие — это последовательность клеток
(`HEX_FIELDS` в `Game.tsx`): чей ход, куда, по кому. `narrow()` идёт по ней и
решает, что подсветить. Разные типы действий сравниваются по одной и той же
последовательности, поэтому ход и «длинная» тактика предлагаются вместе.
Ответ, которому нечего выбирать, даётся кнопкой; необязательный шаг никогда
не срабатывает сам. Подробно — раздел «Как действие выбирается в интерфейсе»
в `docs/RULES.md`.

## Договорённости

- **Не выдумывать правила и данные.** Если карты, текста или ассета не хватает —
  сказать об этом прямо, а не сочинить правдоподобное. Источники: рулбуки в
  `design/rules/`, развёртка карт в `warchest.units.clean/`.
- **Интерфейс по-русски, комментарии в коде по-английски.**
- **Глаголы журнала — в настоящем времени.** В русском прошедшем есть род, и
  «развернул» для Марины неверно.
- Новые правила — только в `@wc/shared`. В клиенте не должно появиться ни одной
  проверки законности хода.
- Числа сверяются с коробкой: сумма монет по наборам (74 базовых, 19 «Осада»,
  18 «Ночная вылазка») закреплена тестами.

## Где легко ошибиться

- **Матч с бюджетом по времени невоспроизводим.** Бот думает по настенным
  часам: те же сиды под другой нагрузкой дают другие партии. Воспроизводимость
  бит-в-бит есть только у бюджета в итерациях (`ismcts-200`), и отлаживать бота
  надо на нём.
- **Матчи меряются временем, поэтому не занимайте все ядра.** `match-pool.ts`
  по умолчанию берёт `ядер − 2`: бот думает по настенным часам, и отнятое ядро —
  это ядро, которое не думало. Обе стороны матча всегда в одинаковых условиях,
  так что сравнение честное, но абсолютные числа на загруженной машине ниже.
- **У каждого эксперимента свой блок сидов.** `lab-cli.ts` сдвигает сид на
  10 000 за эксперимент. Иначе изменение принималось бы за то, что оно удачно
  легло на эти двести раздач, а следующее измерялось бы на раздачах, которые его
  и выбрали.
- **Ручку надо промерить прибором до матча, а не объяснять матч после.** Порог
  «расширяться или углубляться» я сформулировал трижды неверно и каждый раз узнал
  об этом из матча: 25%, потом 4,8%, потом ручка перестала делать что-либо. Пять
  минут инструментирования (сколько посещений получает лучший ход из 600) сразу
  показывают и рабочий диапазон, и то, что его нет. То же с фичами оценки —
  `feature-drift.mjs` показывает, не читает ли фича глубину спуска вместо
  позиции.
- **Ночной прогон надо накрыть `caffeinate`.** У ноутбука `pmset -g` показывал
  засыпание по бездействию через минуту: загрузка процессора сама по себе его не
  удерживает, удерживает только ассерция. `nohup caffeinate -i &` на время
  прогона, и `pmset -g | grep sleep` покажет «prevented by caffeinate».
- **Пересборка `dist` на ходу подсовывает воркеру недописанный файл.** Лаборатория
  создаёт воркеров на каждый эксперимент, и `npm test` в `tooling` тоже зовёт
  `tsc -b`. Поэтому во время ночного прогона правки проверяются через
  `npx vitest run` в `shared`/`bots` (он не пишет `dist`), а полная сборка — по
  окончании эксперимента. На этот случай лаборатория повторяет упавший
  эксперимент один раз.
- **Повтор принятого эксперимента надо писать наоборот.** Предложение с той же
  настройкой после принятия становится «нечего менять» — ноль партий и REJECT в
  отчёте, который выглядит как вердикт. Проверять надо возвратом: выключить
  принятое и убедиться, что стало хуже. Я наступил на это трижды за сутки.
- **Подтверждение против «корня» ломается, если менять умолчания.** Лаборатория
  хранит корень с пустыми ручками, то есть «какие сейчас по умолчанию». Стоит
  перенести принятое в `DEFAULT_SEARCH` — и `against: 'root'` начнёт сравнивать
  уже не с тем, с чего начинали. Если умолчания менялись, стартовую конфигурацию
  надо выписывать в предложении явно.
- **`weights/lab.json` — не то, чем играет сервер.** Это база текущего прогона.
  В `eval.ts` числа переезжают руками и только после подтверждения на свежих
  сидах: принятый SPRT говорит «лучше предыдущей базы», а не «столько-то Elo».
- **Бот сообщает о ходе только после того, как снял себя с очереди.** Сервер в
  ответ на это сообщение сразу просит следующий ход — карта может оставить боту
  добор, а игрок без монет оставляет бота ходить одному. Если поменять порядок,
  этот запрос отскочит от «ход уже в работе», и партия встанет навсегда. Ловится
  тестом `accepts the next request straight from its own notification`.
- **Бот — игрок, а не судья.** Его ход проходит через тот же `applyAction` с
  проверкой, и его рука так же скрыта: клиент получает `viewFor` только для
  живых игроков, места ботов в рассылку не попадают.
- **Рассылка идёт по `rooms.seatedMembers`, а не по `humanMembers`.** Ушедший из
  идущей партии сохраняет место (может вернуться), но за столом уже не сидит.
  Если слать состояние всем, у кого есть место, `game.view` прилетит следом за
  ответом «стола у вас нет» и вернёт человека на экран партии — выход начнёт
  требовать двух нажатий. Ловится тестом в `rooms.test.ts`.
- **Скрытое прячется не только в руках, но и в шагах.** Шаг Воина-жреца несёт
  добранную монету, и `viewFor` вырезает её имя для всех, кроме владельца. Но
  детерминизация — это *состояние*, а в состоянии пропусков нет: движок доходит
  до шага в уверенности, что тот называет монету. Ловится только когда «чей ход»
  и «кто отвечает» расходятся — защищающийся выбирает, куда принять удар, — и
  поэтому пережило фаззер на 4000 партий, смоук и весь набор тестов. Нашлось за
  восемь минут в лаборатории. `sampleDeterminization` теперь досочиняет монету
  из руки того же игрока, как досочиняет саму руку.

- **`simulate` не проверяет ход, `apply` проверяет.** Сервер обязан звать
  `applyAction`/`apply` с проверкой: это единственное, что стоит между
  подделанным сообщением по WebSocket и состоянием партии. `simulate` — только
  для поиска, который сам только что породил ход из `legalActions`.
- **`engine.ts` содержит два больших `switch` по `tactic.kind`:** законность в
  `tacticActions` и применение в `applyTactic`. Имена веток совпадают. Правки
  вслепую (`sed`, `.replace()`) попадают не туда — уже приводило к дублям
  мёртвых веток. Ставить якорь по номеру строки или по уникальному контексту.
- **Геометрия доски восстановлена из арта** и подтверждена схемой сетапа на
  стр. 4 рулбука. Раскладка odd-q, плоская вершина, нечётные колонки ниже.
  Менять `board.ts` только со ссылкой на источник.
- **Стороны стоят по короткой оси поля**, тёмная сверху. Клиент разворачивает
  поле так, чтобы свои базы были снизу — это только экранные координаты,
  идентификаторы клеток не меняются.
- **Клиентская сборка и сервер расходятся,** если забыть `npm run build` перед
  перезапуском сервера. Набор доступных дополнений сервер объявляет сам в
  `auth.ok` — клиент показывает только то, что сервер потянет.

жалобу тестом, потом чинить.
