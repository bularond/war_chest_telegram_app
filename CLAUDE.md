# CLAUDE.md

Telegram Mini App: дуэль по правилам настольной War Chest (Trevor Benjamin,
David Thompson, AEG). Правила и бот — на Rust, приложение вокруг них — на
TypeScript.

Подробности правил и источники — [`docs/RULES.md`](docs/RULES.md), запуск и
боевой режим — [`README.md`](README.md), план компьютерного соперника —
[`ROADMAP.md`](ROADMAP.md). Здесь — карта кода и договорённости.

## Где что живёт

**Движок один, и он на Rust.** Ни клиент, ни сервер, ни тесты не содержат второй
реализации правил. То, что раньше было `packages/shared/src/engine.ts` и
`packages/bots`, теперь `crates/`, а TypeScript обращается к ним через аддон.

```
crates/wc-core        правила: доска, отряды, движок, детерминизация, инварианты
crates/wc-bot         эвристика, оценка, ISMCTS
crates/wc-napi        @wc/core-native — аддон, с которым говорит сервер
crates/wc-tooling     арена, bench, SPRT, SPSA, регрессия, лестница уровней
crates/wc-conformance движок за трубой — сверка с TypeScript, см. ниже

packages/core-native  сборка аддона (.node) и его загрузка
packages/shared       два входа: данные/типы и правила
packages/server       Fastify + WebSocket + node:sqlite
packages/client       Vite + React 19
```

Зависимость строго в одну сторону: всё знает про `wc-core`, `wc-core` не знает ни
про кого. `wc-tooling` знает про `wc-bot`, обратной стрелки нет.

## Команды

```bash
npm install
npm run build                    # аддон → генератор → shared → server → client
npm run typecheck                # + проверка, что generated.ts не устарел
npm test                         # cargo test и весь TypeScript
npm run test:rust                # движок и бот
npm run test:ts                  # 127 shared + 26 сервер + 27 клиент
npm run deploy                   # docker compose up -d --build
npm run dev -w @wc/server        # :8787, node --watch
npm run dev -w @wc/client        # :5173, проксирует /ws на сервер
npm run smoke                    # полная партия через WebSocket по-настоящему

npm run bench                    # во что обходятся операции движка и роллаут
npm run arena -- --a heuristic --b greedy --games 200
npm run sprt -- --a weights/base.json --b weights/новое.json
npm run spsa -- --from weights/base.json --out weights/spsa.json
npm run regress -- --games 5000 --out weights/fitted.json
npm run regress -- --target value --games 250 --out weights/fitted-value.json
npm run ladder -- --budgets 60,250,1000 --games 60
```

Одиночный тест: `cargo test -p wc-core --test fuzz`, `npx vitest run -t "часть"`.

Вне Telegram сервер работает в dev-режиме: подпись не проверяется, личность
берётся из `localStorage`. Чтобы сыграть с собой — второе окно в приватной
вкладке, иначе оба таба сядут за стол одним игроком.

## `packages/shared/src`

Два входа, и это то, что не даёт правилам попасть в браузер.

- **`@wc/shared`** — данные и типы. Ничего нативного. Это всё, что нужно клиенту.
- **`@wc/shared/rules`** — движок, только для Node.

| Файл | Что внутри |
| --- | --- |
| `generated.ts` | **Не править руками.** Печатные факты из `wc-core`: гексы, локации, монеты, тактики. Пишет `scripts/generate-shared.mjs`, `npm run typecheck` падает, если устарело. |
| `unit-text.ts` | Имена, тексты карт, цвета, арт. Это не правило, и в Rust его нет. |
| `units.ts`, `board.ts`, `hex.ts`, `decrees.ts` | Место, где механика из генератора встречается с текстом. |
| `types.ts`, `view.ts`, `protocol.ts`, `opponents.ts` | Только типы и настройки сервера. |
| `rules.ts` | Фасад над аддоном: `createGame`, `applyAction`, `viewFor` и запросы к позиции. |

## Как это работает

**Сервер авторитетный.** `GameState` не покидает сервер; клиент получает
`GameView`, где вырезано скрытое: мешки, чужая рука, монеты, сброшенные рубашкой
вниз. Клиент никогда не считает правила сам — он только сужает список
`view.legal`, который прислал сервер.

**Граница — JSON, и это осознанно.** Состояние — несколько килобайт, ход — одно
действие, так что путь туда-обратно стоит десятки микросекунд там, где ход
занимает у человека секунды. Единственный, кому это было бы дорого, границу не
переходит вовсе: поиск держит состояние на стороне Rust весь ход.

**Шаги.** Всё, что игрок ещё должен решить, лежит в `state.pending` — стек
`PendingStep`, разбирается с конца. Шаг может нести поле `seat`: тогда отвечает
не тот, чей ход, а защищающийся (`acting_seat`).

**Выбор действия в клиенте.** Действие — это последовательность клеток
(`HEX_FIELDS` в `Game.tsx`): чей ход, куда, по кому. `narrow()` идёт по ней и
решает, что подсветить. Подробно — раздел «Как действие выбирается в интерфейсе»
в `docs/RULES.md`.

## Договорённости

- **Не выдумывать правила и данные.** Если карты, текста или ассета не хватает —
  сказать об этом прямо, а не сочинить правдоподобное. Источники: рулбуки в
  `design/rules/`, развёртка карт в `warchest.units.clean/`.
- **Интерфейс по-русски, комментарии в коде по-английски.**
- **Глаголы журнала — в настоящем времени.** В русском прошедшем есть род, и
  «развернул» для Марины неверно.
- **Новое правило пишется в `wc-core` и нигде больше.** Если клиенту понадобилось
  число из правил — оно едет через `catalog.rs` и генератор, а не переписывается.
- Числа сверяются с коробкой: сумма монет по наборам (74 базовых, 19 «Знать»,
  19 «Осада», 18 «Ночная вылазка») закреплена тестом в `units.rs`.

## Где легко ошибиться

- **`json.rs` — единственное место, где потеря поля тихая.** Всё, что выше ядра,
  ходит через эту форму, и поле, которое забыли прочитать назад, не падает:
  партия просто продолжается без него. Ровно так на один коммит пропал журнал, а
  симптом был «бот ходит, а в журнале пусто». Постоянный ответ —
  `crates/wc-core/tests/roundtrip.rs`: состояние и вид, записанные и прочитанные
  обратно, должны совпасть. Любое новое поле — сначала туда.
- **`generated.ts` — производная, а не источник.** Правка руками переживёт ровно
  до следующего `npm run build`. `npm run typecheck` проверяет свежесть.
- **Уровни сложности надо перемерить.** Бюджет в миллисекундах — это не
  сложность, а сложность *при такой скорости кода*, и код стал быстрее в
  пятнадцать раз. `npm run ladder` уже показывает, что на 60 мс поиск обыгрывает
  эвристику всухую: три ступени сейчас не три ступени.
- **Матч с бюджетом по времени невоспроизводим.** Бот думает по настенным часам:
  те же сиды под другой нагрузкой дают другие партии. Воспроизводимость
  бит-в-бит есть только у бюджета в итерациях (`--iterations 200`), и отлаживать
  бота надо на нём.
- **Матчи меряются временем, поэтому не занимайте все ядра.** `arena.rs` по
  умолчанию берёт `ядер − 2`. Обе стороны матча всегда в одинаковых условиях, так
  что сравнение честное, но абсолютные числа на загруженной машине ниже.
- **У каждого эксперимента свой блок сидов.** SPSA сдвигает сид на 10 000 за шаг.
  Иначе изменение принималось бы за то, что оно удачно легло на эти двести
  раздач.
- **Повтор принятого эксперимента надо писать наоборот.** Предложение с той же
  настройкой после принятия ничего не меняет — проверять надо возвратом:
  выключить принятое и убедиться, что стало хуже.
- **`weights/base.json` — не то, чем играет сервер.** В `eval.rs` числа
  переезжают руками и только после подтверждения на свежих сидах: принятый SPRT
  говорит «лучше предыдущей базы», а не «столько-то Elo».
- **Бот сообщает о ходе только после того, как снял себя с очереди.** Сервер в
  ответ на это сообщение сразу просит следующий ход. Если поменять порядок, этот
  запрос отскочит от «ход уже в работе», и партия встанет навсегда. Ловится
  тестом `accepts the next request straight from its own notification`.
- **Бот — игрок, а не судья.** Его ход проходит через тот же `apply_action` с
  проверкой, и его рука так же скрыта.
- **Рассылка идёт по `rooms.seatedMembers`, а не по `humanMembers`.** Ушедший из
  идущей партии сохраняет место, но за столом уже не сидит. Ловится тестом в
  `rooms.test.ts`.
- **`Validate::No` не проверяет ход, `Validate::Yes` проверяет.** Сервер обязан
  звать с проверкой: это единственное, что стоит между подделанным сообщением по
  WebSocket и состоянием партии. Без проверки — только поиск, который сам
  породил ход из `legal_actions`.
- **`engine.rs` содержит два больших `match` по тактике:** законность в
  `tactic_actions` и применение в `apply_tactic`. Имена веток совпадают. Правки
  вслепую попадают не туда.
- **Геометрия доски восстановлена из арта** и подтверждена схемой сетапа на
  стр. 4 рулбука. Раскладка odd-q, плоская вершина, нечётные колонки ниже.
  Менять `board.rs` только со ссылкой на источник.
- **Порядок стопок на доске значим.** `Board` хранит занятые клетки в порядке
  появления, потому что тактика пехотинца читает его задом наперёд. Ход — это
  снять и положить, то есть встать в конец очереди, ровно как `delete` и
  присваивание в JavaScript.

## Тесты

| Файл | Что закрывает |
| --- | --- |
| `wc-core/tests/fuzz.rs` | Случайные партии во всех сочетаниях наборов: инварианты после каждого плая, каждый предложенный ход играбелен, тупиков нет. |
| `wc-core/tests/roundtrip.rs` | Состояние и вид переживают запись в JSON и чтение обратно. |
| `wc-core/src/*.rs` | Геометрия, каталог, ключ хода, суммы монет по коробкам. |
| `shared/engine.test.ts` и далее | Правила и все 28 отрядов — теперь это приёмочный набор Rust-движка. |
| `shared/invariants.test.ts`, `fuzz.test.ts` | Что правила доезжают до TypeScript целыми. Сама проверка свойств — в Rust. |
| `client/app.test.tsx` | Настоящие компоненты поверх настоящего движка. |

Клиентские тесты гоняют реальный `GameState` через `viewFor` и фейковый сокет —
баг в выборе действия ловится здесь, а не на телефоне. Правило: воспроизвести
жалобу тестом, потом чинить.

## Что сверялось при переносе

`scripts/conformance.mjs` играл оба движка от одного сида и сверял после каждого
плая всю позицию по полям, множество легальных ходов, а через ply — состояние
после **каждого** легального хода. 400 партий, восемь сочетаний наборов, оба
размера доски, все три режима драфта: совпало всё, включая журнал. После этого
TypeScript-движок был удалён. Чтобы повторить сверку, нужен коммит до удаления:

```bash
git worktree add ../war_chest_ts 61be27f
```

## Чего пока нет

- **Ночная лаборатория (`lab`) не перенесена.** Очередь экспериментов без
  присмотра, журнал вердиктов и круги спуска остались в истории
  (`git show 61be27f:packages/tooling/src/lab-cli.ts`). Отдельные инструменты
  цикла — `arena`, `bench`, `sprt`, `spsa`, `regress`, `ladder` — работают.
  Скрипты `scripts/lab-*.mjs` читают журнал, которого никто не пишет.
- **Инструменты-измерители удалены вместе с пакетами, которые они читали:**
  `feature-drift`, `root-parallel`, `tactic-audit`, `search-shape` и ещё четыре.
  То, что они намерили, записано в комментариях Rust-исходников; сами они — в
  истории. Правило «ручку надо промерить прибором до матча, а не объяснять матч
  после» осталось в силе, а прибора под рукой сейчас нет.
- **wasm-сборки нет, и она не нужна.** Клиент не исполняет ни одного правила:
  всё, чем он рисует, приходит из генератора. Если однажды понадобится партия в
  браузере без сервера — `wc-core` собирается под `wasm32` как есть, добавить
  надо только обёртку.
